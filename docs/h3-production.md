# H3单人唱歌：从人声与图片到可剪辑的1080片段

2026-09-10追加。这个版本来自第二批实际制作：9个单人唱歌片段已完成技术交付，保留了13次生成尝试的费用和失败记录。它把原生H3生成、内部FFN计算分批、普通放大、接回原曲和最小裁尾整理为一个可复用方法。

这次公开的是一份生成API图和两个阶段的本地工具。生成运行在你配置好的ComfyUI/RH执行端，交付工具运行在本机。公开工具不自动提交付费任务；我们的账户队列、项目调度和输入原素材不在这个包里。另一账号或本地GPU的生成尚未重新验证。

## 输入、动作、产物

| 输入 | 动作 | 得到什么 |
|---|---|---|
| 一张9:16人物图＋一段已提取人声的PCM WAV | 根据人声采样数准备图，交给具备对应模型/节点的执行端 | 864×1536、24fps的H3原生片 |
| 下载的H3原片＋同时间段的完整歌曲PCM WAV | 本机普通放大、30fps适配、最小裁尾、接回原曲 | 1080×1920、30fps的MP4及检查回执 |

人声负责驱动生成；最终听到的伴奏与人声来自原曲切片。两份WAV必须从同一时间线取相同起止，保留头尾停顿，不要各自自动去静音。文件扩展名不能证明已提取人声，工具不会判断WAV里是否还有伴奏。

适用起点是单人、固定竖屏中近景。默认提示描述成年女歌手、录音场景和克制中性表情；换角色/场景时应调整提示并重新看片。多人、侧脸遮挡和强动作不在这批验证范围内。

## 固定了哪些设置

完整参数见 [生产配方](../recipes/h3-singing-production.json) 和它引用的 [基础模型配方](../recipes/h3-light.json)。

- 原生864×1536、24fps、8步、seed42，保留原D05模型、LoRA、注意力和双时钟设置。
- 在LoRA后、DualClock前增加 `MiniMaxH3ChunkFeedForward`：enabled=true、chunks=4、min_tokens=8192。
- 默认使用 [中性演唱提示](../recipes/prompts/singing-neutral.txt)：限制讨好式笑容，同时允许发音需要的张口和露齿。提示词不是对表情/口型的硬性保证。
- 本地采用Lanczos普通等比例放大，输出1080×1920；H.264 CRF16，AAC320k，30fps。
- 30fps通过普通重复原帧得到，原速播放。没有AI插帧、新增运动细节、FlashVSR或自动美颜；后续是否在剪辑软件美颜由使用者决定。

FFN4把部分内部计算拆成4批，再放回原位置，视频的时间段并没有切成4段。它可能减少这部分中间张量的峰值，但模型权重、注意力和解码还有自己的开销。带节点成功也不证明每层都实际触发分块，更不代表总显存降到四分之一。节点来自 [ComfyUI-sol-attn](https://github.com/Saganaki22/ComfyUI-sol-attn/blob/930a4d6e432ff8b8ed5e30ff2f72519b92d69bdf/minimax.py)，与T8另一份ActivationChunk实验节点分开。

这批的审美取舍是保留H3高原生再普通放大：之前对照里，FlashVSR让耳环/麦克风更清楚，同时可能加重脸部加工感。该取舍只代表当前人物和素材，不代表AI超分对所有镜头都更差。

## 1．准备生成图

需要Python 3.10+。两个新工具均使用Python标准库。媒体整理另需FFmpeg/FFprobe在PATH中；本次包装在Python3.12和FFmpeg7.1环境核验。

```sh
python tools/prepare_singing.py --vocal-wav local-inputs/vocal.wav --image portrait.png --audio vocal.wav --output local-output/singing.api.json
```

`--vocal-wav`是本机文件，用来准确读取采样数；`--image`与`--audio`是执行端可识别的文件名或自己的上传引用。请确认执行端收到的是同一份人声，可用工具输出的SHA256核对。改提示可以追加 `--prompt your-prompt.txt`。

命令只写JSON并打印长度计划，不上传、不运行模型、不消费。示例 [API图](../workflows/h3-singing-production.api.json)用9.2秒占位；应为自己的WAV重新准备，不能照搬示例帧数。

执行端仍须具备图里的全部节点与模型，新增FFN节点必须真实可用。没有节点时先核对安装/部署，不要默默删掉节点后称为同配方。RH用自己的正常入口和权限；保存、API资格与付费仍按平台要求处理。

这是 `class_type/inputs` 执行图，**不是带鼠标位置和连线布局的ComfyUI前端画布JSON**。它可交给支持prompt API的执行端，也可根据参数在自己的画布中配置。公开本地工具不会替代这一生成环节。

## 2．下载原片，接回原曲并交付

准备好与人声同起止的完整歌曲切片 `mix.wav`，其中可以包含伴奏。若只有完整原曲，可按自己的切段表精确到采样切出它，例如以下仅示范第480000至960000采样：

```sh
ffmpeg -n -i local-inputs/full-song.wav -af "atrim=start_sample=480000:end_sample=960000,asetpts=PTS-STARTPTS" -c:a pcm_s16le local-inputs/mix.wav
python tools/finalize_singing.py --video local-inputs/h3-native.mp4 --mix local-inputs/mix.wav --output local-output/1.mp4
```

工具先拒绝尺寸不符、时间戳不连续或画面短于音频的原片，再从原生片一次完成放大、帧率适配、裁尾与接原曲。它会完整解码成片、检查每帧时间戳、音画长度、画幅及原曲零偏移波形匹配，然后生成 `1.mp4` 与 `1.delivery.json`。波形匹配用于确认接回了原曲，**不是嘴型评分**；AAC是有损编码，不宣称声音逐字节不变。

已有输出不会覆盖。断线后可检查已有文件；若编码未产出最终文件，重新调用只做本地处理，无须重付生成费：

```sh
python tools/finalize_singing.py --video local-inputs/h3-native.mp4 --mix local-inputs/mix.wav --output local-output/1.mp4 --check
```

输出目录需支持本地硬链接，例如NTFS/ext4/APFS，便于以不可覆盖方式交付；不支持时会报错。保留原生片，以后调整导出参数无需重新生成。程序生成的本地回执也应留在忽略的输出目录中。

## 长度到底如何控制

生成先求 `ceil(人声采样数×24÷采样率)`，再向上取最近的 `17n+5` 合法帧数。它请求能覆盖声音的最短合法长度，没有额外固定加一秒；实际下载后还要核对真实帧数，不能用长音轨掩盖短画面。

交付保留 `ceil(原曲切片采样数×30÷采样率)` 帧。原曲保持原速、不平移、不剪短；画面只裁掉声音结束后的余尾。

- 切点恰好落在30fps格子上：声音和视频严格等长，尾巴为0。
- 其他切点：视频向上覆盖，余尾小于1/30秒。多段直接堆放可能累积误差，应按原曲切点排到时间线。
- 24→30的普通重复帧不是AI补帧；30fps也不代表细节或口型更准确。
- H3原片若真的少于声音，工具报错，保留证据；不通过额外定格填充冒充生成完整。

这批9段恰好全部在30fps格上，总2771帧、92.366667秒。曾在另做复制流拼接时碰到约21毫秒起点偏移，随后修正了拼接验证；这不代表任意拼接命令或剪辑软件都能无条件直接堆放。用户在剪辑软件中的整体使用反馈仍单列。

## 实际花了多少，有哪些失败

原始公开字段见 [第二批账目](../data/h3-production-batch-002.json)。

| 路线 | 尝试结果 | RH币 |
|---|---|---:|
| 原D05，24G | 4次显存失败 | 本批账户核对未观察到额外扣费；API费用字段为null |
| 原D05，48G | 1段成功 | 153 |
| D05＋FFN4，24G | 8段成功 | 555 |
| 合计 | 13次尝试，9段完成技术交付 | 708 |

FFN4八段的人声长度约9.53—10.57秒，原D05/48G一段11.33秒。FFN4中7段用了公开的中性提示，1段仍用先前提示。成功任务的RH报告时长为311—381秒；该数不是剔除加载等开销后的纯GPU计算时间。

四次失败的API秒数为0，不代表机器没有工作；费用null也不等于所有失败免费。这批综合实际账户差额核对708币、未结0。不能只报8次成功而隐去此前的失败，更不能把8/8外推为通用成功率或证明显存下降了多少。

本地9段裁尾、放大和检查的历史耗时之和181.576秒，两路重叠执行；含拼接排查的那轮墙钟363秒，新增RH费用0。它不是当前便携脚本跨机器的性能承诺。人声/字幕准备、提示选择、审片和剪辑美颜需要人工，未完整计时，因此人工时间与“每个最终采用秒的有效成本”保留未知，不写0。

本批输出已通过技术核验；逐字口型、美感和最终采用由人判断。没有做固定素材的完整有/无FFN消融，没有记录实际GPU型号与完整显存曲线，也未完成其他账号的生成复跑。
