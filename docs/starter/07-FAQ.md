# 常见问题、恢复和有效成本

**我是不是还得一直问给我包的人？**
通常不用。让你自己的Codex先读入口、对应说明、脚本与现有日志，给你说清楚下一步。真正缺的是你账号权限、素材、费用许可或审美决定时，由它问你。报告Bug时给版本、命令、错误、图的类名、尺寸/时长和脱敏回执，不要给Key。

**为什么看起来还是旧工作流名字？**
平台可能按提交使用的载体工作流显示名称。实际运行什么必须看 `submitted.api.json`、节点/模型和回执，不凭任务名字猜。完整图字段是官方高级API的一种用法，不意味着任意服务都不需要可用工作流或账号资格。

**说有了模型，为什么还跑不起来？**
模型权重、LoRA、文本编码器、VAE、自定义节点和它们的接口都要存在且兼容。读 `data/h3-required-models.json`核对，缺哪项具体报哪项；不能用名字相似的模型默默替换。原图在平台能跑、重建API图还没在你账号跑过，也要区分。

**画面糊、皮肤像油画，怎么办？**
按层看：实际参考图 → H3原生 → 普通放大 → 最后美颜/超清。检查是不是意外576小样、图像过小、播放器缩放、编码太狠或叠加了增强。先同帧并排，不一次换五个参数。本包默认864原生，不把1080文件名当原生细节。

**脸远、脸小，是必须重生成吗？**
先看是裁切比例还是透视本身。普通裁近可改善脸在画面的占比，不能改变透视关系。保留旧版，裁切预览后再决定是否重付生成。

**为什么人物笑了、间奏仍唱、突然长出麦克风？**
看首图、人物表情、提示和驱动音频是否冲突。麦克风等明确硬伤可以按预算返工；小笑是否需要重做由项目偏好决定。间奏/只演镜头可以单列静音驱动，但它仍不是闭嘴100%保证。

**H3是不是永远比别的模型便宜又好？**
没有这个结论。本包来自特定输入和路线；原生尺寸、时长、实例、失败率与人工操作都影响有效成本。口型、皮肤质感、动作、多人和镜头控制分别比较，不能只看一张漂亮截图。

**不想卡在8–12秒的长段怎么办？**
先看显存报错位置。FFN4只拆部分内部计算，不保证注意力/解码不爆显存。可以在合理音乐边界拆镜，或在授权里试48G/另一个分批方案；拆成多个镜头与“一个长镜头无缝延续”是不同能力。

**我重启、关聊天了，任务会不会没了？**
看 `rh-state.json`的taskId。云端已提交任务可能继续运行；新聊天读取它并query/download，不重新submit。局部文件工作未完成时看manifest、输出和日志；先验证已有产物再复用。这个便携包没有常驻Windows队列，别把退出聊天当作自动继续发下一镜。

**音频长一点/短一点或成片逐渐错位？**
看是否选择同一原曲版、完整人声是否去掉静音、采样表是不是共享、视频是否真的少帧、切点是否在30fps格上、字幕起点是否减了两次。按绝对原曲位置排片，不拿近似小数逐段相加。规则见 [时间轴](05-Timing.md)。

**成本怎么记？**

记录每一次，包括失败、返工和没采用的；把平台RH币、其他模型费用、主动操作、机器等待、用户参与分别记。未知项为null。总生成费用除以最终采用秒数才是“有效生成成本/秒”；没有采用时长就暂不算。不要把失败费用缺失填0，也不要把任务耗时当纯GPU时间。

`templates/attempt.example.json`给了字段。串行小样先核真实费率，再扩大；整批预算须扣去已花和已提交未结的预留。原作者历史几百币的批次不能直接当你下一首的报价。

**是不是开源了某个角色？**
公开/分享代码、说明、少量视频各有范围。工具可以配你自己的角色和音乐，不自动获得原作者角色、整曲或商业字体的权利。来源见[致谢](../credits.md)，具体范围见[许可](../../LICENSES.md)。

**以后换新模型或大神新工作流，怎么接？**
先固定当前可用版本，写清新方法替换的是图像生成、视频引擎、驱动接法还是后处理。用同一小段与旧版对照，记录费用/失败/人审。值得采用再另建配方版本；不要在线覆盖当前冻结工程，把所有进行中项目一起升级。
