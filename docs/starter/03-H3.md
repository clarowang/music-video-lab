# 当前 H3 工作流怎么工作

H3 是生成引擎；T8等节点负责把图片、音频、采样与解码接在一起；本包再负责逐镜输入、长度、收片与交付。不是上传一张照片就把全部创作决策交给模型。

驱动音频统一PCM16，收片先核原片声音再接原曲；转换与检查命令见[H3音频兼容入口](../h3-audio.md)。原图音只读，24位/浮点原件另存派生副本。

## 这次交出的主配方

| 项目 | 默认值 | 人话解释 |
|---|---|---|
| API图 | `workflows/h3-singing-production.api.json` | 18个节点的执行图，无账号绑定 |
| 模型/LoRA/编码器 | 以实际JSON字符串和 `data/h3-required-models.json` 为准 | 是当时跑通的组合，不猜平台已经部署最新模型 |
| 原生尺寸 | 864×1536，9:16 | 最终1080是后续普通等比例放大 |
| 生成帧率/采样步数 | 24fps / 8步 | 本配方不是T8的6+2渐进路线，也不是按广告替换成4步 |
| FFN | 开，4块，min_tokens=8192 | 分批做模型内部一部分计算，减轻该部分显存压力 |
| seed | 42 | 便于核对，换种子不保证质量更好，也不保证跨服务完全同片 |
| 原片保存CRF | 19 | 视频编码参数，不是模型采样步数 |
| 交付 | 1080×1920 / 30fps | Lanczos普通缩放、普通帧率转换、原曲回接 |

FFN分批不是把视频分成四段再拼，也不等于所有注意力、解码和中间张量都不占显存。原使用方的长段仍发生过24G显存不足；2–15秒是准备工具接受范围，不是“15秒内必成功”。先用短代表片核你自己的服务，升级48G要按预算决定。

节点职责可以这样读：

| 执行链 | 解决什么 |
|---|---|
| UNETLoader + 注意力配置 + LoRA | 装入已验证的模型组合，决定主要生成方法 |
| MiniMaxH3ChunkFeedForward | 模型内部FFN分批 |
| LoadImage / LoadAudio / 文本编码器 / VAE | 读图、读音、理解提示、编码与解码 |
| MiniMaxH3AudioConditioningT8 | 把图、音频、尺寸、帧数和输入模式组合成条件 |
| RandomNoise / 调度器 / MiniMaxH3DualClockSamplerT8 | 按指定种子和8步执行生成 |
| T8解码 + VHS_VideoCombine | 把生成结果还原为帧并保存视频 |
| 本机 finalize_singing.py | 核长度、普通放大/帧率转换、裁尾、铺回准确原曲 |

详细类名、输入和连线以JSON为准；不要拿概念图重建时遗漏LoRA、编码器或注意力配置。

## 三种已整理的输入接法

| mode | 图片怎么用 | 驱动音频 | 适合先试什么 |
|---|---|---|---|
| reference-audio | Ref2VA人物/画面参考，不严格钉住第0帧 | 通常人声，也可明确选混音 | 单人唱歌、自由一点的动作 |
| first-frame-audio | Hybrid，把参考图同时接first_frame | 人声或混音 | 希望从给定构图出发的唱/说/动作 |
| first-frame-silent | Hybrid首帧，同时把音频角色设静音 | 真正全零、等长WAV | 只演、听别人说、反应或插镜 |

本包 `project.json` 的 `mode` 和 `drive` 显式控制接法。只演镜头的 `drive=silence` 不会把最终原曲静音。尾帧、视频动作参考、长镜头、多音轨多人控制等不是这个18节点便携配方已交付的功能；要用时单列变体，不凭模型大类“支持多模态”就冒充本包已接好。

## 提示写动作，不靠形容词堆质量

```text
The adult singer in the reference image sings the supplied vocal audio.
Keep the recognizable face, hairstyle and outfit. Clear natural articulation,
relaxed jaw, restrained expression, subtle breathing and occasional blinking.
Close handheld selfie viewpoint, very small natural camera drift.
No visible phone, microphone, captions or added text. No broad smile or theatrical grimacing.
```

不笑不等于不动嘴。只要求“保持冷淡、完全不动”可能压住表演，过度要求“开心唱歌”又会改变人物气质。唱、只演、慢走、固定镜头要逐镜写明，不能把旧录音棚提示混进自拍镜头。

## 画质和口型分别验收

原生片与普通放大版应并排比较。FlashVSR在原使用方的某些H3脸上有更强的涂抹/油画观感，饰品可能反而更清楚，因此这套路线把它从默认交付里拿掉；这不是对FlashVSR所有输入的判决。

24→30fps在本包里是普通重复/取帧，不会生成新的中间动作。美颜由用户在剪辑工具里自行决定。检查口型要听对应原曲看连续视频，重点看可辨认的唇音、起音、停口和长音；波形相关性只验证音轨来源/时间，不能作为口型得分。

API图可以给执行服务；它不是包含节点位置、拖线UI、插件安装信息的完整鼠标画布。便携方案的主路是 [RH高级API](04-RunningHub.md)。若要ComfyUI本机运行，还需自己的硬件、权重、节点和版本验证，本包未在新本机GPU上验收。
