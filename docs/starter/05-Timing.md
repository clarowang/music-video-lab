# 让音频、视频和剪辑用同一个时钟

最重要的是保存歌曲中的真实位置。第3段不是“一个大约8秒的视频”，而是“原曲从某个采样到另一个采样的区间”。生视频和剪辑都读取同一张表。

## 本包的简单严格路线

- 原曲与人声都转换成48kHz、16-bit PCM WAV；转换另存，不覆盖原件。
- 两条完整音频具有相同起点、长度；如果分离工具删掉开头静音或尾巴，先查明偏移再另存对齐版。长度相等仍不能证明对齐，需听头中尾并核波形/标记。
- 制作切点选在30fps的帧格上。48kHz下每帧正好1600个采样，`start_sample`与`end_sample`都是1600的倍数。
- 所有镜头覆盖一段连续原曲，不重叠、不漏间奏；每段符合本配方2–15秒接受范围。

原曲/人声规范化示例，执行前确认源文件：

```powershell
ffmpeg -n -i "你的原曲.mp3" -vn -ar 48000 -ac 2 -c:a pcm_s16le "work/song/project/inputs/mix.wav"
ffmpeg -n -i "你的人声.wav" -vn -ar 48000 -ac 2 -c:a pcm_s16le "work/song/project/inputs/vocal.wav"
```

WAV更大不等于模型更吃力：模型主要吃解码后的音频与视频张量，不是按MP3/WAV文件大小决定难度。本包用PCM WAV是为了精确取样、避免反复有损编码和容器偏移。采样率、声道和内容仍需符合节点。

## 切点怎么从SRT得到

SRT提供一句话的大致区间，不是每两个条目必切一刀。让Codex先听语义、尾音和气口，再定分镜切点。已有认可切点不要为了机械整齐擅自改。

候选时间`t`可以先算 `round(t×30)` 得到附近帧，再乘1600得到采样位置。四舍五入可能向两边移动约16.7毫秒；如果刚好切掉字头/尾音，就换一个合适的帧，而不是仍称精确原切点。多个相邻镜头共用同一个边界，不能两边分别取整后留缝。

每镜例子：

```json
{"id":"01","start_sample":48000,"end_sample":193600}
```

表示原曲1秒开始，到4.033333…秒结束；持续145600个采样 = 91帧/30fps。结束点按半开区间理解：下一段从193600继续，不重复上一个采样。

`vocal_alignment_reviewed=true`必须是检查之后的记录，不能为通过验证直接改成true。

## 生成为什么还会长出来一点

当前配方把声音长度换算成24fps，再往上取到最近的合法 `17n+5` 帧数。以正好10秒为例，需要240帧，最小合法长度是243帧，即10.125秒。它没有无故固定加一秒，只是模型计算有长度格子。

收片后本机再保留对应的300帧/30fps、铺回10秒原曲，尾巴归零。先检查原生画面真的覆盖声音，再裁多余部分；不能用音轨很长来掩盖画面已经结束。

如果你的切点必须保留在任意采样，公开核心可以交付ceil(采样数×30/采样率)帧，画面余尾小于1/30秒，但多段直接相加可能积累误差。**本便携组装器故意拒绝这种输入**，请让Codex另做按绝对采样位置排片的版本，不去偷偷拉伸音频。现成严格路线最好懂、也最适合首轮复现。

## 哪些不是“对齐”

生成时给模型相同时长与真实人声，能约束内容和覆盖，但不能用后期裁尾修复所有咬字偏差。后期整理只管时间轴、尺寸与音轨，不会把错误唇形自动改对。

普通24→30fps不做AI插帧；连续原曲不变速、不因转场缩短、不对每镜重新对齐到不同位置。最终检验包含帧数、PTS起点/连续性、原曲波形和完整解码，连续口型与听感仍需人看。
