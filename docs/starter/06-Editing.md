# 剪辑方案：先保住音乐，再做包装

主线是本机FFmpeg完成可复跑的组装，按共同时间轴顺排画面，铺一条连续原曲，加可编辑ASS字幕与开头歌名。用户要美颜等效果时，再进自己熟悉的剪辑软件做一遍。

这次便携版提取了原制作中的关键方法，但没有把原作者机器上的全部剪映工程、坐标控制器、字体和大量字幕实验搬过来。当前交出的自动样式是浅色柔影整句字幕、开头标题、硬切或短淡化；更复杂的逐字艺术字幕可以在独立版本继续做，不能把别的项目一次试片当成通用默认。

## 先收齐哪些东西

`batch-v1/manifest.json`、`continuous-mix.wav`、每镜 `jobs/<编号>/mix.wav` 与 `clips/<编号>.mp4`。使用本次选定版本，别从同名旧文件夹里混入一个返工前镜头。

字幕：提供UTF-8 SRT。`project.json` 的 `subtitles_clock=song` 表示SRT时间属于完整原曲，组装时扣除选段起点；`clip` 表示已经从本次成片0秒计时。只转换一次，不能两边都减起点。

中文字体：选择你本机已安装、且自己有权使用的字体。用 `--font` 写字体内部家族名，用 `--font-file` 给TTF/OTF文件；脚本把你自己的字体复制到本次本地输出以便复跑，本包不分发商业字体。名称与文件不匹配可能回退，务必看实际字形。

## 方案A：先做严格硬切底版

```powershell
python tools/studio.py assemble --batch "work/你的项目/batch-v1" --out "work/你的项目/edit-v1" --font "Microsoft YaHei" --font-file "你自己的中文字体.ttf"
```

这条以0帧转场执行。1080×1920、30fps、不变速、没有画面整体拉伸或增益。原曲只编码为一条AAC音轨，0dB，不把每段片内音频分别拼来拼去，避免重复压缩和缝隙。AAC仍是有损编码。

输出有 `final.mp4`、`review.html`、`captions.ass`、`captions.json`、`verification.json` 与可复用的画面分块。先看这个版本确定时间、歌词、画面顺序正确，再做效果。

## 方案B：接缝加很短的融合

```powershell
python tools/studio.py assemble --batch "work/你的项目/batch-v1" --out "work/你的项目/edit-v2" --transition-frames 8 --font "Microsoft YaHei" --font-file "你自己的中文字体.ttf"
```

8帧约0.267秒。工具取切点前后各4帧，在接缝局部复制边缘帧做淡化，使这8帧仍占原来的8帧；**没有拿两条完整片重叠后把整首缩短**。声音始终走自己的连续时间线。

这是一个效果取舍：叠化会出现短暂重影，也可能影响接缝附近的唇形。优先放在气口/间奏；咬字很重要时硬切更稳。帧数支持0或不超过30的偶数，不把大转场自动套全曲。

## 字幕和歌名怎么改

默认浅色整句字幕在画面下方，有轻微描边/阴影和80ms显隐；换行使用SRT里你实际确认的换行，**脚本不擅自重写歌词或按字数乱断句**。较长中文句由Codex结合语义拆两行，再另存字幕版本。标题默认顶部三秒，位置不是作者IP的固定品牌模板；人脸或平台按钮挡住时按你的构图设计。

`captions.ass`可读、可修改，不是黑箱。颜色、字号、边距、字体、时间和 `\pos/\move/\fad` 等效果都能让Codex解释。正式改版保留已有输出；纯字幕修改可基于 `picture.mp4` 和原曲重新叠字，不需要再花钱跑H3。本包命令为安全起见默认新建输出目录；若要复用缓存作更快改版，让Codex先核哈希再操作。

可选的[原词对齐工具](../lyrics-alignment.md)提供逐句和逐字 SRT。逐字字幕需要可靠字级时间，只有逐句SRT不能声称每字精确；静音/零时长字、拖长音和识别错词要局部校正。艺术效果要在实际人物背景上审，不能只看灰底样机。

## 如果你更习惯剪映

可以把无字幕 `picture.mp4` 和连续原曲导入剪映，再导入本次时间轴SRT、加美颜/文字；也可以直接导入已包装的 `final.mp4` 只做轻美颜。后者已有字幕无法像独立轨道一样任意改字。

保持9:16、1080和30fps；确认没有二次填充、裁窄、上下黑边和误拉速度。默认先只试轻美颜，超清、AI补帧和4K增强另做对照。原使用方曾在最高档处理里感到锐化和边缘闪动，并不认为效果全开就更好。会员和可用功能以你自己的账号为准，本包不保证免费。

本包不写剪映私有草稿结构，不带原机器鼠标坐标，也不会接管你的电脑反复点窗口。你的Codex可以做文件方案，具体GUI步骤按你当前版本读回确认。

## 最后交付与复看

机器检查：输出1080×1920/30fps、总帧数正确、PTS从0连续、音频覆盖精确区间、原曲同位置相关性、完整解码、输入哈希不变。任意一项失败先看报告，不用“可以播放”替代验收。

人看：每镜人物一致性、连续嘴型、停口/间奏、表情、移动/手、边缘闪动、接缝重影；整首听音量、断音、混音是否正确，检查字幕文字/时间/遮挡。把有问题的镜头号和秒点写在日志里。

技术通过后状态是“待人审候选”。你认可哪些镜头、哪些要重做、整片是否发布，分别记录。不要把单次生成成功直接计算成100%可用率。
